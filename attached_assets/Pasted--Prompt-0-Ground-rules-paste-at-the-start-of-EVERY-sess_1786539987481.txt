## PHASE 1 — Multi-Tenancy & RBAC Foundation
**MC-BRD refs:** FR-ADM-04, NFR-05/09 · **Removes VoxAgent constraints C1, C3**
**Why first:** every later table (campaigns, DNC lists, connectors) needs `tenant_id`. Doing this last means re-migrating everything.

```
TASK: Convert VoxAgent from single-tenant to multi-tenant with RBAC.

1. Create tables: `tenants` (id, name, slug, status, region, created_at) and
   `users` (id, tenant_id FK, email, password_hash, role, status). Roles:
   OWNER, ADMIN, SUPERVISOR, ANALYST.
2. Additive migration: add `tenant_id` (FK -> tenants.id, indexed) to EVERY
   existing domain table: calls, bots, personas, persona_traits,
   persona_config, conversation_config, llm_config, flow_configs,
   memory_entries, message_logs, calendar_invites, email_agent_config,
   writing_style_profiles. Backfill all existing rows to a seeded tenant
   'default' so the running system keeps working unchanged.
3. Convert the three singleton config tables (persona_config,
   conversation_config, llm_config) to one-row-per-tenant. Config lookups
   become "by tenant_id" with the seeded default as fallback.
4. Auth: session-based login (email+password, bcrypt) issuing a signed
   session containing user_id, tenant_id, role. Add Express middleware
   `tenantScope` that (a) rejects unauthenticated API requests except
   /v1/health and telephony webhooks, and (b) automatically filters every
   Drizzle query by session tenant_id. Telephony webhooks
   (/v1/calls/receive) authenticate by a per-tenant webhook secret header
   and resolve tenant from the called DID (add table `tenant_dids`:
   tenant_id, did_e164 unique).
5. RBAC middleware `requireRole(minRole)`: ANALYST=read-only, SUPERVISOR=
   +call ops (transfer/conference), ADMIN=+config/persona/bot CRUD,
   OWNER=+user management & billing.
6. REMOVE the single-active-persona constraint (PE-02): personas are now
   activated PER BOT, not system-wide. Add `bots.active_persona_id` FK.
   Keep the activation validation gate (PE-03/PE-18) exactly as-is, applied
   at per-bot activation. Update dashboard persona UI: "Activate" becomes
   "Assign to bot ->" with a bot picker.
7. Audit log: table `audit_log` (tenant_id, actor_user_id, action, entity,
   entity_id, before_json, after_json, ip, created_at). Write an entry from
   middleware for every mutating request on personas, bots, configs, users.
8. Dashboard: login page, tenant name in the header, user management screen
   (OWNER only), and role-hidden UI controls.

ACCEPTANCE: two seeded tenants A and B with one user each; user A can never
read or mutate any B row via any endpoint (prove with tests); existing
default-tenant data still fully functional; audit_log rows written on
persona edit.
